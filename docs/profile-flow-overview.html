Automation Folder MCP Enablement

Install Once, Open a Tab, Use the MCP Tools

This demo page is for non-technical users. Each tab shows one simple flow with logo-style icons, dotted moving arrows, the command to enable that profile, and the tools/result users can expect. Only one profile is active at a time.

Install Flow

This is the common flow for every project. The team copies the Automation folder, selects one profile, restarts the IDE, and then asks Copilot or Windsurf normally.

Profile commands ./Automation/setup_copilot_mcp.sh jira ./Automation/setup_copilot_mcp.sh gitlab ./Automation/setup_copilot_mcp.sh test ./Automation/setup_copilot_mcp.sh review ./Automation/setup_copilot_mcp.sh dev
1

Copy Folder

Place the portable Automation/ folder inside the project repository.

2

Add Local Config

Put private credentials and project values in Automation/.env.local.

3

Run Profile

The setup command installs dependencies and writes MCP config for the chosen profile.

4

Restart IDE

Copilot/Windsurf reloads the MCP configuration and sees only selected tools.

5

Ask Normally

The IDE starts the selected MCP server on demand and calls its tools.

Simple message for stakeholders: install the folder once, choose one profile command, restart the IDE, and use the assistant normally.

Jira Flow

Use this profile when the team wants to read, prepare, or update Jira stories in a controlled way.

Enable Jira tools./Automation/setup_copilot_mcp.sh jira
1

Enable Jira Profile

Only jira-mcp tools are exposed in the IDE.

2

User Asks

Example: “Read or update Jira story BDRSP-1413.”

3

Read Full Jira

Reads title, description, acceptance criteria, regulatory field, comments, subtasks, linked work, and feature context.

4

Approval Gate

If update is needed, the user sees planned changes before Jira is modified.

5

Story Ready

Jira is clean, separated by fields, and ready for implementation.

jira_read_story
jira_feature_context
jira_analyze_story
jira_refine_story
jira_manage_subtasks
jira_check_connection

Dev Flow

Use this profile for the end-to-end governed workflow. It exposes one controlled tool and internally coordinates Jira, GitLab, Test, and Review logic.

Enable DevFlow tool./Automation/setup_copilot_mcp.sh dev
1

Enable Dev Profile

Only dev_implement_story is exposed to keep the workflow controlled.

2

User Asks

Example: “Implement Jira story BDRSP-1413.”

Read and Analyze

Reads Jira story, parent feature, related stories, and repository structure before action.

Approval Gates

Delivery Evidence
