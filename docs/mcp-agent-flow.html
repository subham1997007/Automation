DevFlow Sequence

The end-to-end story implementation path with two approval gates.

01
Start User asks the AI agent to implement a Jira story.
02
Read and Analyze dev-mcp reads the full story, scans the codebase, and proposes Jira field updates.
G1
Jira Update Approval AI asks before updating Jira fields or the one-subtask action.
03
Branch and Code Branch is checked or created. AI applies minimal project code changes.
04
Test and Review DevFlow collects test scope, reports, review risks, and AC coverage.
G2
MR Approval AI stops before push and merge request creation.
05
Template DevFlow must read .gitlab/merge_request_templates/Default.md.
06
Create MR Branch is pushed and GitLab MR is created after safety checks pass.

Safety Rules

A plain-language checklist for keeping DevFlow focused, reviewable, and safe to adopt.
