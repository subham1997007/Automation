Role: Developer

What's automated for Developers

Dev Flow · Agent 5
⚙️

End-to-End Story Implementation

Say "implement BDRSP-1413" → agent reads story, validates ACs, analyses codebase, proposes changes, runs tests, and prepares MR — all gated by your approval at each step.

GitLab Flow · Agent 2
🌿

Safe Branch & MR Management

Auto-creates feature branches with correct naming, writes governed MR descriptions with AC coverage, risk summary, and test evidence. Blocks unsafe actions (force-push to main, etc.).

Test Flow · Agent 3
🧪

Auto-detect & Run Tests

Detects project type (Maven, npm, etc.), discovers test commands, executes suites, summarises pass/fail evidence, and attaches results directly to the MR.

Review Flow · Agent 4
🔍

Pre-MR Code Review

Reviews changed files against story ACs, identifies missing tests, flags risks, checks Checkstyle/PMD compliance, and produces a readiness summary before the MR is raised.

🚦

Story Readiness Checks

Instantly check whether a story has description, ACs, regulatory justification, and correct parent feature link before sprint planning — no manual checklist needed.

🗂️

Subtask Planning

Agent suggests minimal, scoped subtasks based on story scope and codebase analysis. SM approves the plan before subtasks are created in Jira.

Pulls parent feature context, lists completed, in-progress, and pending stories — giving SM a clear sprint health view without leaving the IDE.

Safety & Control

You are always in control

1

Proposal First — Never Silent Writes

Every agent shows a proposal (story update, code change, MR description) and waits for your explicit "yes" before writing anything to Jira, GitLab, or the filesystem.

2

Memory — Agents Remember Context

LangGraph-powered memory keeps track of prior decisions, story history, and team preferences — so agents don't ask the same questions twice.

3

Guardrails — Agents Can't Go Rogue

Each agent has hard-coded safety rules: no force-push to protected branches, no applying story updates without parent Feature, no skipping regulatory justification.

4

Profile Isolation — Least Privilege

Each profile exposes only the tools needed for that workflow. A test profile can't touch Jira. A Jira profile can't push code. Tools are siloed by design.

Live Example

Agent reads Jira story

②

Codebase analysis + Jira update proposed

Agent scans repo, identifies impacted files (UsecaseUtil, ObservabilityAspect), proposes Jira story update. Awaits developer approval.

③

Code changes implemented

After approval, agent implements the two new constants, Rhapsody branch logic, metric mapping, and Javadoc. Awaits another approval.

④

Tests run → Review → MR drafted

Maven tests run automatically, review checks AC coverage and PMD/Checkstyle, MR description is written with evidence. Developer opens the MR with one click.

Get Started

Up and running in 4 steps

📁

1. Copy

Copy the Automation/ folder into your project repo

🔑

2. Configure

Add your Jira & GitLab credentials to the local env file

▶️

3. Run

Run start.sh --profile jira (or dev / gitlab / test / review)

💻

4. Restart IDE

Restart Copilot / Windsurf — agents are live immediately

Pro tip: Each profile activates only the tools relevant to your role. POs use the jira profile. Devs use dev or gitlab. SMs use jira. No profile exposes tools it shouldn't.
